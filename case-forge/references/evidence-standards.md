# 证据标准

案例的可信度由证据等级决定，不由文笔决定。本文件定义分级规则、数据口径要求和标注规范。

## 证据四级

| 等级 | 定义 | 处置 |
|---|---|---|
| 已证明 | 有成品链接、上线截图、数据看板、可验证的第三方记录 | 可直接写入终稿 |
| 待证明 | 用户声称发生过，但暂无材料支撑 | 追问补齐；补不齐则降级或删除 |
| 可迁移 | 来自相邻行业/业务的经验 | 建立与目标岗位的映射后使用，标注"可迁移" |
| 缺口 | 确实不存在的经历 | 禁止编造；转为学习计划或在叙事中诚实绕开 |

## 数据口径要求

每条量化结果必须能回答五个问题，答不出的标注"口径待核实"，不删除也不夸大：

1. **定义**：指标的准确定义是什么（如"转化率"指哪一步到哪一步）？
2. **基线**：改动前的数值是多少？
3. **周期**：数据采集的时间窗口？
4. **归因**：如何确认是设计改动带来的，而非同期运营活动或季节因素？
5. **边界**：这个结果里，个人贡献与团队贡献如何切分？

示例：

- ❌ "改版后转化率提升 30%"
- ✅ "注册流程第二步到完成的转化率，从 41% 提升到 53%（改版前后各两周数据）；同期无运营活动，我负责流程重构与表单设计，视觉由另一位设计师完成"

## 事实来源三分法

任何材料进入案例前，先标明来源，三类来源在写作中必须保持可区分：

- **公开事实**：公司官网、帮助中心、公开报道中的产品信息。可用于交代业务背景。
- **个人事实**：用户本人确认的职责、决策与结果。案例的主体。
- **分析推断**：根据公开信息和个人事实推导的合理猜测。只能作为访谈草稿，用户确认前禁止写入终稿。

## 口语化材料的转写规则

用户口语描述 → 案例语言的转写中：

- "我们做了……" → 追问"你具体负责哪部分"后再决定用"主导/负责/参与/协作"。
- "效果挺好的" → 追问具体指标或可见变化；补不到数据就改写为定性描述（如"客服相关工单明显减少"），不硬编数字。
- "大家都很认可" → 追问是谁、在什么场合、以什么形式认可；转化为可验证的表述（如"方案在季度评审中被定为团队标准流程"）。

## 待证明内容的处置优先级

1. 优先补：用户能提供截图、文档、数据导出的。
2. 其次替：用同项目内已证明的其他证据替代该论点。
3. 降级写：改为定性描述或明确标注边界。
4. 最后删：无法补齐且不构成案例主线的，删除。
