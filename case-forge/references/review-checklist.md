# 案例体检清单

用于阶段 4 的自检，也可独立用于诊断已有作品集。按招聘者的真实阅读顺序排列——前面不通过，后面不会被看到。

## 30 秒测试（招聘者扫描层）

招聘者平均给每个案例的第一轮时间是 30 秒。模拟扫描，只读标题、首屏和图注：

- [ ] 不看正文，能否说出这个案例解决了什么问题？
- [ ] 能否看出结果（数字或明确的业务变化）？
- [ ] 能否看出作者的角色与边界（主导/负责/参与）？
- [ ] 能否看出业务背景（行业、产品类型、用户规模量级）？

任何一项答不出，说明首屏失效，返回重写首屏，而不是补充正文。

## "所以呢？"测试（论证层）

逐段追问"这段证明了什么只有作者能做的事"：

- [ ] 每一段都指向一项能力证据，没有纯流程描述？
- [ ] 关键决策点都交代了"为什么不是另一个方案"？
- [ ] 至少有一个被放弃的方案或失败的尝试？
- [ ] 结果部分区分了个人贡献与团队贡献？

## 可信度测试（细节层）

面试官用细节探测真实性：

- [ ] 每条数据能说清口径（定义、基线、周期、归因）？
- [ ] 提到的协作对象具体（角色、分歧点、如何达成共识），不是"和产品经理紧密合作"？
- [ ] 约束条件真实（时间、资源、技术限制），不是真空中的完美方案？
- [ ] 复盘中至少有"如果重来会改什么"？

## 视觉证据测试（呈现层）

- [ ] 每张图承担论证功能（证明决策、对比前后、展示复杂度），无纯装饰大图？
- [ ] 过程稿只保留改变方向的决策点快照，未堆放全部中间稿？
- [ ] 敏感数据已脱敏（真实用户头像、内部数据、未发布功能）？
- [ ] 移动端阅读时信息层级仍然成立？
- [ ] 导出 PDF 后分页、字体、图文对应关系正常？

## 组合层测试（多案例）

- [ ] 第一个案例对应目标岗位最核心的能力要求？
- [ ] 任意两个案例不使用同一叙事模式（问题驱动/系统构建/验证迭代/0→1）？
- [ ] 全部案例合读，能力覆盖无重复证明、无关键缺口未解释？
- [ ] 首页叙事与各案例结论一致，无事实矛盾？

## 诊断报告格式

体检输出按严重度分级：

| 级别 | 含义 | 示例 |
|---|---|---|
| P1 | 会导致招聘者放弃阅读 | 首屏无结论、数据无法解释口径 |
| P2 | 会在面试追问中翻车 | 角色表述夸大、缺少取舍叙事 |
| P3 | 影响质感但不致命 | 图文节奏失衡、装饰图过多 |

每条发现给出：位置、问题、修复动作。不给没有修复动作的发现。
