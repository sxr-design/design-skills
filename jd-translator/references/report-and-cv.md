# 匹配报告与 CV 重写规范

## 报告是否必要

报告的价值是保存“为什么这样分方向、为什么选这些项目、为什么需要这些版本”的决策依据，并为后续提问、补证、CV 重写和面试准备提供同一事实底稿。

按场景选择：

- **不需要完整报告**：只有一个岗位、证据充分、用户只需要快速改写。输出一页简版结论即可。
- **需要完整报告**：多个岗位需要聚类、方向差异明显、证据缺口多，或用户需要决定准备几份材料。

不要为每个公司机械复制报告。若一份简历可以覆盖，生成一份合并报告；只有材料确实需要拆分时，才按简历方向生成报告，并在每份报告内保留该方向各岗位的决定性差异。

## 分方向匹配报告内容

完整报告默认包含：

1. 一句话结论：直接回答优势、短板和材料版本建议。
2. 该方向覆盖的岗位及选择依据。
3. 高频岗位能力、通用能力和低频待确认能力。
4. 逐维度“候选人证据 / 公司要求 / 当前水平”。
5. 已证明、待证明、可迁移、真实缺口与硬门槛。
6. 方向内各岗位的决定性差异及面试官疑问。
7. 作品集或案例排序。
8. 需要候选人补充的问题。
9. 投递前补强计划。
10. 一份材料是否足够；若不足，该方向的 CV 和作品集策略。

## HTML 报告

当用户要求 HTML 时：

- 首屏不必展示姓名或岗位名称；优先展示“优势是什么、短板是什么”。
- 副文案用具体项目证据解释结论，不写假大空概括。
- 先展示高频岗位能力，再将通用能力收进紧凑的基础资格区。
- 多公司比较只展示会改变筛选结果、案例选择或面试准备的差异。
- 低频但关键的能力使用“需确认”状态，不与真实缺口混淆。
- 使用有效图形比较同维度能力，避免装饰性图表。
- 可使用 Remix Icon：
  - 勾：已证明。
  - 感叹号：待证明或可迁移。
  - 叉：当前未证明或真实缺口。
- 小 Tag 使用约 4px 圆角，大提示条使用约 8px 圆角。
- P1/P2/P3 使用独立优先级 Tag，不与默认有序列表重复。
- 章节编号与标题保持相近字号，间距控制在约 12–24px。
- 导航保持紧凑；内容较多时使用横向吸顶导航，避免占用大块侧栏。
- 多公司能力模块可使用展开/收起：
  - 公共能力始终可见。
  - 点击公司 A 时展开 A 并收起 B。
  - 点击公司 B 时反向切换。
  - 保留键盘操作、移动端适配和打印时全部展开。
- 装饰图形置于内容底层，不遮挡文字。
- 支持桌面端、移动端和 A4 打印。

## 导出安全

- 同时提供 HTML、Markdown 和 PDF 时，保持三者结论一致。
- Markdown 使用本地静态文件下载。
- PDF 优先由本机浏览器或可信本地工具预生成，再用本地链接下载。
- 不在包含私人简历内容的本地页面中运行未经审查的第三方 PDF 转换脚本。
- PDF 生成后渲染为图片检查分页、字体、表格和图形。
- HTML 更新影响正文后重新生成 PDF；只修改打印时隐藏的顶部操作栏时可不重生成。

## CV 重写前置条件

开始前至少确认：

- 目标岗位与公司。
- 最近经历与时间线。
- 2–3 个重点项目的业务场景、角色、行动和结果。
- 关键指标口径或待核实状态。
- 英文及全球化工作的真实证据。
- 目标行业直接经验、可迁移经验与真实缺口。
- 地点、远程、签证或工作许可。

信息不足时继续提问，不用模板填满空白。

## CV 架构

默认先写一份事实底稿，并优先尝试生成一份可覆盖全部目标岗位的 CV。只有方向判断确认无法清晰覆盖时，才产生多个版本：

1. 姓名与联系方式。
2. 方向能力标签。
3. 自我评价：使用“【能力名称】+ 经验概括 + 项目范围 + 结果证据”。
4. 工作经历。
5. 教育与必要补充信息。

不同版本允许使用不同的能力标签、自我评价能力项和项目组合。

## 信息层级

严格保持用户现有简历的嵌套结构，不把子标题拆成新的并列模块：

```text
工作经历                                  ← 唯一主章节
└─ 公司名称 / 市场与业务标签 / 职位 / 时间  ← 公司条目
   ├─ 重点项目名称                         ← 公司条目下的子标题
   │  ├─ 项目描述                          ← 项目下的子标题
   │  └─ 我的成就                          ← 项目下的子标题
   │     ├─ 【能力标签】行动与结果
   │     └─ 【能力标签】行动与结果
   └─ 重点项目名称
      ├─ 项目描述
      └─ 我的成就
```

“工作下的重点项目”“项目描述”“我的成就”都属于工作经历内部的信息层级，不得各自新开独立大段落。公司、项目和成果之间通过字号、字重、缩进和间距表现从属关系。

## 页数与信息预算

- **默认目标：一页 A4。**
- **允许上限：两页 A4。**
- 只有删减后会失去目标岗位的关键证据，且继续压缩会明显损害可读性时，才使用两页。
- 不通过极小字号、过窄行距或过密排版强行塞进一页。
- 一页版优先保留：
  1. 方向定位与 3 项左右核心能力。
  2. 最近且最相关的 2–3 段公司经历。
  3. 能覆盖高频岗位能力的重点项目。
  4. 可解释的结果指标。
- 优先删除或压缩：
  1. 通用设计流程和重复职责。
  2. 与目标方向关联弱的旧项目。
  3. 同一能力的重复证明。
  4. 不能说明业务含义的数据。
- 每家公司按相关性保留 1–2 个重点项目；每个项目通常保留一句项目描述和 1–3 条“我的成就”。
- 两页版也应先完成内容取舍，不得把事实底稿原样堆入。

## 经历写法

每个项目使用：

**项目描述**

> 在【业务/用户场景】中，负责【项目范围】，解决【核心问题】，并取得【最重要结果】。

**我的成就**

> 在【业务/用户场景】中，负责或主导【明确范围】，通过【关键行动与判断】，实现【结果与影响】。

规则：

- “项目描述”负责交代背景与总体结果；“我的成就”负责证明个人能力，避免重复同一句话。
- “我的成就”中的每条继续使用【能力标签】，但标签必须具体且与目标方向相关。
- 先写业务问题与复杂性，不堆设计流程名词。
- 动词准确区分“负责、主导、推动、参与、协作”。
- 量化结果放在同一条中，但不省略指标含义。
- 重要项目说明规模、市场、用户或业务背景。
- 一条只表达一个主要成果。
- 删除无法支持目标岗位的低价值职责。
- 不重复“设计方案、原型、评审”等资深设计师默认动作，除非它构成特殊影响力证据。

## 多方向定向

保持事实不变，只调整叙事重点：

- **全球化/快速迭代型岗位**：前置多市场、用户研究、完整 UI/UX、迭代速度与业务结果。
- **金融交易型岗位**：前置风险、支付、资金、规则、异常状态、可信体验与研究验证。
- **AI 工具型岗位**：前置复杂工作流、模型边界、可解释性、失败状态、人机协同与评估。

交付时提供：

- 共用事实底稿。
- 若一份足够：只交付一份完整 CV。
- 若必须拆分：交付每个方向的完整 CV，不把“换项目顺序”当作唯一差异。
- 每个方向覆盖的公司与岗位。
- 每个方向的作品集案例顺序和首页叙事。
- 仍待用户确认的占位项。
- 不适合写入 CV、但面试必须准备的回答。
